# PhoneAgent Web Console

这是一个与 `src/phoneagent` 核心运行时分离的本地调试界面。它只依赖 Python 标准库和
PhoneAgent 已有依赖，不需要 Node.js，也不需要修改或重新构建前端资源。

## 启动

先完成 PhoneAgent 的正常安装和 `.env` 配置，然后在仓库根目录运行：

```bash
uv run phoneagent-web --open-browser
```

如果不希望自动打开浏览器：

```bash
uv run phoneagent-web
```

浏览器访问：

```text
http://127.0.0.1:8765
```

自定义端口：

```bash
uv run phoneagent-web --port 9000
```

## 会话行为

Web 服务每次启动会执行一轮与 CLI 一致的检查：

1. ADB 可执行文件
2. 已连接并授权的 Android 设备
3. ADB Keyboard
4. 截图与视觉观察
5. 视觉模型 API

页面会先显示独立的预检界面，此时后方的主控制台处于虚化且不可交互状态。检查通过后
会自动进入主控制台；如果检查失败，则停留在预检界面，并可在修复环境后点击“重新检查”。

检查通过后创建一个 PhoneAgent 实例。只要 Web 服务进程没有退出，后续任务都会复用
这个实例和检查结果；刷新或重新打开浏览器不会触发检查。停止并重启服务时，才会创建
新的检查会话。

当前版本一次只执行一个任务。这样可以避免两个 Agent 线程同时控制同一台手机。

## 页面功能

- 使用对话式工作台提交任务：左侧展示历史任务，底部输入新任务，主体区域默认只展示最新工作进展
- 工作过程中，新进展会覆盖上一条摘要；点击工作过程卡片可展开查看完整执行轨迹，完成后重点展示最终结果
- 模型响应摘要优先显示结构化思考，并在协议校验失败时回退显示原始模型内容和独立的格式错误提示
- 提交自然语言任务并查看当前工作阶段；详细步数、动作、验证和恢复信息收纳在可展开的完整过程内
- 直接消费统一的 `AgentEvent`，实时查看阶段、模型响应、结构化动作、执行、验证和恢复
- 分别展示 `command_success`、可观察结果和确定性语义证据
- 在浏览器中确认敏感操作
- 在需要验证码、密码或受保护页面时等待人工接管
- 在运行或等待人工操作时手动停止当前任务；Agent 会在最近的安全检查点结束并保存轨迹
- 任务结束后绘制逐次模型请求的 Token、耗时和估算费用曲线，历史轨迹详情同样可见
- 浏览、搜索、查看并下载 `runs/trajectory_*.json`

轨迹仍由 PhoneAgent 核心运行时写入，Web Console 只读取并展示，不改变 schema。
页面中的“最近思考、动作和验证”来自事件流，不依赖 `AgentState` 保存历史副本。

## 配置

设备、模型和运行时参数继续读取仓库根目录的 `.env`。Web Console 额外支持：

```dotenv
WEB_HOST=127.0.0.1
WEB_PORT=8765
APP_LAUNCH_TIMEOUT_SECONDS=15
INPUT_PRICE_PER_1M_TOKENS=0
OUTPUT_PRICE_PER_1M_TOKENS=0
COST_CURRENCY=CNY
```

前两项也可以通过命令行的 `--host` 和 `--port` 覆盖。应用启动超时同时适用于 Web
Console 创建的 PhoneAgent 设备实例；应用名称仍由核心静态别名表在执行 `Launch` 时解析。

两个 Token 单价均以“每 100 万 Token”为单位。保持为 `0` 时仍会显示 Token 和耗时曲线，
但不计算费用；配置厂商对应的输入、输出单价后，页面会显示单次与整次任务的估算费用。

## 安全说明

Web Console 能够控制已连接的 Android 设备，并能读取包含任务、动作和模型输出的轨迹。
当前服务不包含登录或权限系统，因此默认只监听 `127.0.0.1`。不要直接绑定公网地址；
如果确实需要远程访问，应自行增加反向代理、TLS 和身份认证。
